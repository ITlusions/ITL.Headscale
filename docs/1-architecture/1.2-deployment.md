# 1.2 Deployment

## Prerequisites

- The OIDC client secret (`headscale-oidc-secret`, key `client-secret`) must exist before login will work at all - either let the `KeycloakOIDCClient` CR create it (`keycloak.enabled: true`) or create it by hand first.
- `ITL.Keycloak.Tenants` must already be deployed and the `itlusions` realm's groups (`vpn-users` at minimum) must exist - see [2.2](../2-authentication/2.2-keycloak-claims-gotchas.md).

## Deploy

```bash
cd itl.headscale
helm upgrade --install headscale . -n itl-headscale --create-namespace
```

Config changes (anything in `templates/configmap.yaml`) need the pod to actually restart to take effect - the Deployment's `checksum/config` annotation (a hash of the rendered ConfigMap) handles this automatically. If a config change doesn't seem to apply after `helm upgrade`, check that annotation exists on the Deployment template before assuming the config itself is wrong - this exact gap caused a real, repeated SSO failure in `ITL.Headscale.UI` (stale `redirect_uri` surviving three redeploys) before being fixed there.

## After deploying: generate Headplane's API key

`ITL.Headscale.UI` needs an API key to manage this server - generate it only after this chart is running:

```bash
kubectl exec -n itl-headscale deploy/headscale -- headscale apikeys create
kubectl create secret generic headplane-headscale-api-key \
  -n itl-headscale-ui --from-literal=api-key=<the key printed above>
```

## Add a user/device

No per-device config file to generate and hand out, unlike `ITL.Wireguard` - the user runs the Tailscale client and logs in:

```bash
tailscale up --login-server=https://headscale.itlusions.com
```

They're sent through Keycloak. Whether they're actually allowed to join is controlled by `oidc.allowedGroups`/`allowed_users`/`allowed_domains` in `values.yaml`'s `oidc` block - see [2.1](../2-authentication/2.1-oidc-setup.md).

## Verify

```bash
kubectl get pods -n itl-headscale
kubectl logs -n itl-headscale deploy/headscale
curl -s https://headscale.itlusions.com/health

# Who's actually registered, and is the subnet router's routes approved:
kubectl exec -n itl-headscale deploy/headscale -- headscale nodes list
kubectl exec -n itl-headscale deploy/headscale -- headscale nodes list-routes
```

## Why SQLite, not Postgres

Headscale's own docs now call Postgres "highly discouraged - only supported for legacy reasons," reversed from older guidance that recommended it. SQLite on a persistent volume is current upstream's recommendation.
