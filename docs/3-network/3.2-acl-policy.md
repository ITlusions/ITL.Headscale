# 3.2 ACL policy

## Why one exists at all

With no ACL policy configured, Headscale logs a repeating warning (`"Failed to read the ACL policy for groups"`) and falls back to its implicit default: every registered device can reach every other device. The warning is harmless but noisy, and "no policy" is a worse starting position than "an explicit policy that happens to currently allow everything" - the latter is something to tighten later; the former is nothing to build on.

## File mode, not database mode

Headscale supports two ACL policy modes. This chart uses **file mode**:

```yaml
policy:
  mode: file
  path: /etc/headscale/policy.hujson
```

Not the top-level `acl.policy_mode`/`acl.policy_path` keys - that was an incorrect first guess (inferred from a CLI error message's wording) that failed live with `"reading policy from path ''"`. The real structure is a **top-level `policy:` block**, confirmed against upstream's `config-example.yaml`.

`headscale policy set` and the REST `PUT /api/v1/policy` endpoint only work when `policy.mode: database` - both were tried and refused with `"update is disabled for modes other than 'database'"`. File mode was kept deliberately (consistent with this chart's existing declarative-file pattern for everything else), rather than switching to database mode to make those commands work.

## How the policy file gets into the pod

Mounted via a Helm-templated ConfigMap - `files/policy.hujson` → `.Files.Get` → ConfigMap → volume mount in `templates/configmap.yaml`. Fully declarative, no runtime file transfer needed. (`kubectl cp` was tried first and abandoned - the Headscale image has no shell at all, so even `tar`-based copy mechanisms can't work against it. The ConfigMap approach also preserves HuJSON comments through the mount, confirmed via `headscale policy get`.)

## The current policy

```hujson
{
  // Minimal, explicit policy - deliberately matches Headscale's IMPLICIT
  // default behavior with no policy at all (every registered device can
  // reach every other device) rather than restricting anything new.
  //
  // Headscale ACL groups need real, already-registered Headscale/Tailscale
  // usernames - NOT Keycloak group names, those are two separate systems.
  "acls": [
    {
      "action": "accept",
      "src": ["*"],
      "dst": ["*:*"],
    },
  ],
}
```

Set 2026-10-24, replacing "no policy exists" with something real to tighten later.

## Tightening this later

Headscale ACL groups (the `"groups"` section of the policy, not used yet) reference real, already-registered Headscale/Tailscale usernames - not Keycloak group names. These are two separate authorization layers: Keycloak's `oidc.allowedGroups` controls who can join the tailnet at all; Headscale's ACL policy controls what a device can reach *after* joining. Revisit scoping this down once there are enough real registered devices/users to write a meaningful policy against.
